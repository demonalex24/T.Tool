# 世界树工程格式

一个工程是一个本地文件夹。打开、保存和迁移由桌面主进程处理；界面通过 `window.desktop` 调用文件操作。

```text
雾港纪事/
├─ project.json
└─ media/
   ├─ image-唯一标识.png
   └─ image-另一标识.jpg
```

`project.json` 使用 UTF-8 JSON。它只保存文字、模块、关系图和媒体元信息；图片内容在 `media/` 中。迁移工程时应复制整个文件夹。软件导出的 ZIP 根目录包含 `project.json` 和整个 `media/` 目录，单独复制 JSON 不会带走图片。另存工程应选择空文件夹。

## 版本 1

```json
{
  "format": "t-tool",
  "schemaVersion": 1,
  "id": "project-唯一标识",
  "name": "雾港纪事",
  "createdAt": 1780000000000,
  "updatedAt": 1780000000000,
  "tree": [],
  "records": {},
  "canvases": [
    {
      "id": "canvas-唯一标识",
      "name": "未命名画布",
      "graph": { "nodes": [], "edges": [] },
      "snapshots": [],
      "viewport": { "x": 0, "y": 0, "z": 1 }
    }
  ],
  "presets": [],
  "wiki": [],
  "timelines": []
}
```

时间为 Unix 毫秒。ID 用来稳定识别对象，与名称无关。名称、类型、正文、标签、模块和关系描述均允许空内容，没有强制档案类型或模块。

### 项目树和档案内容

`tree` 是嵌套数组，每项为 `{id, name, type?, children?}`。`type` 是用户自由文本，不能变成系统枚举。父档案也可以有正文和模块；层级只表示收纳，不表示业务约束。

`records` 是以档案 ID 为键的内容字典。节点图片不属于档案附件，因此不会写入 `records`；导入节点图片只复制文件并返回媒体元信息，节点保存时将路径写入 `canvases[].graph.nodes[].imagePath`。

每项为：

```json
{
  "tags": ["第一幕"],
  "body": "自由正文",
  "modules": [],
  "media": [
    {
      "id": "media-唯一标识",
      "name": "灯塔.png",
      "path": "media/image-唯一标识.png",
      "mime": "image/png"
    }
  ]
}
```

新增树项会得到空档案内容。删除档案及其子孙会移除对应的 `records` 项。修改名称、类型、层级不会更换 ID，正文和模块保留。内容字典与项目树由 `reconcileProject` 同步。

图片的 `path` 必须相对于工程文件夹，统一使用 `/`，例如 `media/a.png`。不要写绝对路径、盘符、`..`、网络地址或 `file://` URL。界面展示媒体时由桌面层将相对路径解析为可读资源；JSON 本身不保存机器相关地址。原文件名由 `name` 保留，实际文件名使用唯一标识，避免同名覆盖。

### 模块和预设

模块接口沿用设计系统的 `ArchiveModule`：`{id, kind, title, data}`。当前支持 `text`、`number`、`axis`、`radar`、`bool` 五种。数值模块的 `value` 使用字符串以保留用户原样输入；倾向轴使用 -100 到 100 的数字；布尔值允许 `true`、`false`、`null`，其中 `null` 表示未设定。

`presets` 保存 `{id, name, modules, updated?}`。预设的模块没有档案模块 ID，只保存结构：

| 模块 | 保留 | 清空或归位 |
| --- | --- | --- |
| 文本 | 标题 | 文字为空 |
| 数值 | 标题、行名、单位 | 数值为空字符串 |
| 倾向轴 | 标题、两端名称 | 游标归中，值为 0 |
| 雷达 | 标题、满分、维度名称 | 维度分值为 0 |
| 是/否 | 标题、问题、选项名称 | 值为 `null` |

导入预设会为每个模块生成新 ID，并复制模块数据后追加到当前档案；不会覆盖既有模块，也不会让多个档案共用可变数据。

### 关系画布和快照

每张画布的 `graph`、`snapshots`、`viewport` 独立。`viewport` 可省略，`z` 表示缩放倍率。

方块为 `{id, kind, title, x, y, archiveId?, archive?, type?, parent?, collapsed?, archiveDeleted?, displayNameEdited?, imagePath?}`：

`imagePath` 可选，必须是工程相对路径且严格匹配 `media/...`；禁止绝对路径、盘符、反斜杠、查询片段、`..` 和工程外文件。打开、保存、导出会检查该路径，媒体缺失只提示，不会把路径改写为机器相关地址。

- `kind` 为 `ref`（档案引用）或 `note`（便签）。引用的 `archiveId` 指向项目树中的档案。
- `title` 是画布显示名；`archive` 是档案原名。画布改名不修改档案。
- `displayNameEdited` 表示用户是否自改显示名。未自改的显示名随档案改名更新；自改名称保留。旧工程缺少此标记时，先比较旧 `title` 与旧 `archive`，再同步原名。
- `parent` 只表示画布内从属关系。新建子级便签和从属虚线属于同一次画布状态更新，不更改项目树。
- 档案被删除后引用方块以 `archiveDeleted: true` 标记，显示“档案已删除”。原方块及关系保留，便于创作者辨认原有关系；档案原名缓存也保留。

关系为 `{id, from, to, label, labelPosition?, labelWidth?, labelHeight?}`，有向。相同 `from` 和 `to` 的重复关系由交互层拦截；反向关系允许。标签可以为空。

1.0.1 新增三个可选字段：`labelPosition` 是文字框中心在所属连线上的比例（0 到 1），缺省使用原设计的中点或反向线的 42%；`labelWidth`、`labelHeight` 是画布坐标中的宽高，范围分别为 48–640、24–320。旧工程没有这些字段时保持原有胶囊尺寸。拖动框只修改比例，拖动角落以中心为基准对称调整大小；移动方块或缩放视口时，框随连线及画布缩放。调转方向会把原位置投影到新的线段，重新计算比例。撤销和快照包含这些字段；格式版本仍为 1。

快照为 `{id?, label, time, auto?, graph?, counts?}`。可回退的快照必须包含完整 `graph`；只有 `counts` 的历史摘要不能用于恢复。快照图是历史状态，重命名、删除档案或同步当前引用时都不会改写它。恢复快照前先存下当前图为“回退前自动保存”，再恢复所选图；快照恢复只作用于画布，不恢复档案正文或项目树。恢复后的当前图需要重新同步引用，识别现在已经不存在的档案。

## 世界观维基目录

`wiki` 是树状目录数组。每个 `WikiEntry` 至少包含 `{id, title, body, tags, updatedAt}`，并可带 `kind: 'folder' | 'entry'` 与 `children`。`folder` 用于收纳子项，`entry` 用于词条；词条不强制关联档案，`archiveIds` 仅在需要时使用。每个维基 ID 在整棵维基树中唯一，目录深度不超过 128。

读取旧的 schemaVersion 1 平铺维基时，缺少 `kind` 的项按 `kind: 'entry'` 处理并保留在根数组，不自动创建目录、不改变 ID、不移动正文或关联。成功保存后才写出带 `kind` 的当前结构；原始 `project.json` 在保存前仍受锁和原子写入保护。

## 兼容、恢复与内存

`format` 与 `schemaVersion` 用于识别格式版本。读取时先解析和验证，再在内存中迁移；成功保存后才写出当前格式。缺少 `schemaVersion` 或值为 `0` 时，仅接受含 `tree` 数组，以及 `records` 字典或 `archives` 数组的旧工程。`archives` 按其档案 `id` 转为 `records`；缺失的 `tags`、`body`、`modules`、`media` 补为空，画布缺失的 `snapshots` 补为 `[]`。迁移不替用户补模块或固定类型。

未知字段在根对象、项目树、档案、模块数据、维基树、关系图和快照中保留。已知字段按当前编辑结果重建，因此从列表或树中删除的条目、节点、子项不会通过未知字段合并重新出现。较新版本（`schemaVersion > 1`）和其他软件的 `format` 明确拒绝打开或覆盖；不尝试按版本 1 降级。当前版本校验已知字段和 ID 唯一性，不把校验失败的工程当成空工程。

已有工程在停止编辑约 1.8 秒后自动保存，也可手动保存。保存先写入并同步临时文件 `project.json.<uuid>.tmp`，将上一次有效文件原子更新到 `project.json.bak`，再原子替换 `project.json`。临时备份使用 `project.json.<uuid>.bak.tmp`，操作完成后清理临时文件。

`project.json` 损坏且备份有效时，打开过程读取 `project.json.bak` 并明确提示已恢复；此时还没有覆盖损坏的原文件。下一次保存修复 `project.json`，但不会把损坏文件写进有效备份。备份也损坏时报告失败，不会覆盖原工程。媒体缺失时文字内容仍可打开，媒体路径保留供后续恢复。

打开工程后，桌面层使用 `.t-tool.lock` 记录进程、主机和唯一令牌。仍在运行的另一个窗口不能同时写同一工程；同机已经结束的进程留下的锁可恢复。保存前用 SHA-256 检查磁盘文件是否被外部改动，发生变化时停止覆盖并提示重新打开。正常关闭释放本窗口的锁。

当前文件层限制：`project.json` 最多 64 MiB；树从根档案起深度不超过 128；图片支持 PNG、JPEG、GIF、WebP，单张大于 0 且不超过 50 MiB、4000 万像素。相对媒体路径拒绝目录穿越、符号链接与工程外文件。图片导入和 ZIP 导出使用有界流式处理，图片头部检查最多读取 1 MiB。

数据模型按引用共享未修改的对象：树项、档案内容、关系线和历史快照不会因为一次改名被整体复制。`reconcileProject` 建立一个 O(档案数) 的临时 ID 索引，逐张扫描当前引用；仅复制有变化的节点数组及节点。树遍历使用 O(深度) 的迭代栈，避免深层收纳导致递归栈溢出。加载 JSON 本身仍需要容纳一个完整工程；特别大的媒体不应以 Base64 填入 JSON。工程导出应流式读取媒体，不把整包图片一次性读进内存。

`scripts/verify-model.mjs` 验证空工程、预设内容剥离、导入独立 ID、删除引用保留关系、快照不变、未知字段保留及 20,001 层树遍历，并对 25,000 个档案与引用的单项改名采样耗时和堆增量。采样增量含临时索引，不代表整个桌面应用的进程峰值。
